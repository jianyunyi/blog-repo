# 免费域名：StackRyze 图文教程——一个账号领 4 个二级域名，indevs.in 与 sryze.cc 已进 PSL、还能接 Cloudflare

**一句话导读：** StackRyze Domains 是个免费二级域名服务，一个账号可以领 4 个不同后缀的域名，自带 DNS 解析、还能接 Cloudflare，有效期 1 年、续期免费；我按官方文档逐条核实：免费是真的、免绑卡、新注册目前开放，但要注意三点——每账号配额官方文档自己打架（现行 FAQ 写 4 个、旧文档写 5 个，本文按 4 个、实际以后台为准），续期是在后台点「Renew」按钮而不是论坛说的「刷新页面」，4 个后缀里只有 2 个进了公共后缀名单（PSL），选后缀优先挑这两个。

## StackRyze 是什么

StackRyze Domains 是一个免费二级域名注册服务，由 Stackryze 团队运营（同一团队还做 Stackryze DNS 解析服务），项目在 GitHub 上开源（仓库 stackryze/FreeDomains，AGPL-3.0 协议），2026 年 7 月发布了 1.0 正式版、开放公开注册。

它给的不是 `yourname.com` 这种归你所有的独立域名，而是挂在它 4 个主域名下面的二级域名，比如 `yourname.indevs.in`。平台只提供域名和 DNS 解析，**不提供服务器和网站空间**——网站内容还是放在你自己的服务器或 GitHub Pages、Vercel 这类平台上，再用解析指过去。

## 4 个后缀怎么选

注册时从 4 个后缀（官方称「命名空间」）里挑一个，注册后**不能更换**，想换只能删掉重注册（还要等冷却期）。

| 后缀 | 官方定位 | 是否在公共后缀名单（PSL） |
| --- | --- | --- |
| indevs.in | 最早的主力后缀，存量名字最多 | ✅ 已进 PSL |
| sryze.cc | 最短，项目里很受欢迎 | ✅ 已进 PSL |
| ryzedns.org | 开放社区向 | ❌ 未查到 |
| nx.kg | 最紧凑，偏工具和服务用 | ❌ 未查到 |

「进了 PSL」有什么用？公共后缀名单是浏览器、证书机构和密码管理器共同参考的一份名单：后缀在名单里，你领到的名字会被当成一个独立注册域名对待——不同名之间的 Cookie 互相隔离、证书机构可以按你的名字签发 TLS 证书、密码管理器按名隔离凭据。官方文档声称每个注册名都会提交 PSL，但我去 PSL 官方名单（publicsuffix.org）实际核对，目前只有 `indevs.in` 和 `sryze.cc` 在名单里（提交方署名就是 Stackryze），另外两个还没查到。**建议优先选 indevs.in 或 sryze.cc**，兼容性最稳；只是挂个内部小工具、不在意这些的话，nx.kg 最短也无妨。

## 规则速览

以下来自官方 FAQ、管理文档与生命周期文档（文档更新时间 2026 年 7 月），核实时间为 2026 年 11 月：

| 项目 | 规则 |
| --- | --- |
| 价格 | 100% 免费，无隐藏费用 |
| 每账号配额 | 4 个，每个后缀各 1 个（见下方口径提示） |
| 有效期 | 注册起 1 年 |
| 续期 | 到期前 60 天开放，免费，点 Renew；每次 +1 年（从原到期日起算），每天最多续 1 次，多次可叠加 |
| 过期宽限 | 15 天：期间解析照常、仍可续期；第 15 天删除解析，再冷却 7 天，第 22 天起开放抢注 |
| 注册方式 | 邮箱 + 密码（官方推荐）或 GitHub 登录 |
| 命名规则 | 3–63 字符，仅小写字母、数字、连字符，不能以连字符开头或结尾 |
| 保留名 | www、mail、admin、api、dashboard、ns1–ns4、含 stackryze/indevs 的名字等不可注册 |
| 删除 | 立即删除解析、不可恢复；名字进入 7 天冷却期（原主人也不能注册），之后先到先得 |

**配额口径提示（官方文档自相矛盾）**：现行 FAQ、管理文档、产品介绍三处都写「4 个、每个后缀各 1 个」；但官方入门页、1.0 版更新日志和旧版文档站仍写「默认 5 个」。本文按更新更晚、口径一致的三处文档取 4 个；你实际注册时以后台提示为准。不够用的话，可以发邮件到官方支持邮箱申请增加配额。

## 注册领取步骤

**第 1 步：打开官网建号**
打开 **domain.stackryze.com**，点右上角 **Get Started**。两种建号方式：

- **方式 A（官方推荐）：邮箱 + 密码**。点 Get Started / Register，填姓名、邮箱和密码（至少 8 位），完成 Cloudflare Turnstile 人机验证，点 **Create Account**，再输入邮箱收到的 6 位验证码确认。
- **方式 B：GitHub 登录**。点 Login，切到 GitHub 页签授权登录。注意：官方故障排查文档写明，**GitHub 账号需注册满 7 天**才能用，刚注册的 GitHub 小号会被拒。

（早前旧文档曾提到 GitHub 新注册暂停，现行文档与 1.0 更新日志均为开放公开注册，邮箱注册也不再依赖 GitHub。）

**第 2 步：进入注册页**
登录后点左侧边栏的 **Register Domain**。

**第 3 步：填名字、选后缀**
输入想要的前缀名并选好后缀，系统会实时查可用性：🟢 绿勾 = 可用，🔴 红叉 = 已被注册或不符合规则。规则：3–63 个字符，只能用小写字母、数字和连字符，不能以连字符开头或结尾（如 `myproject`、`john-portfolio` 可以，`ab`、`-myproject` 不行）。

**第 4 步：提交注册**
勾选同意《服务条款》和《隐私政策》，完成 hCaptcha 验证，点 **Register Domain**。注册立即生效：默认分配官方 NS（`ns1.stackryze.com`、`ns2.stackryze.com`），有效期 1 年，之后在 **My Domains** 里管理。

**注意**：名字注册后不能改名。填错了可以在 15 天内删除重注册，但被删的名字要等 7 天冷却期结束才重新释放，别指望删完马上抢回来。

## DNS 设置：自带解析与接 Cloudflare

### 方式一：用自带 Stackryze DNS（默认，够用）

注册完默认就用官方解析，在解析后台直接加记录即可。支持的记录类型很全：A、AAAA、CNAME、MX、TXT、SRV、CAA 等经典类型都有，还有 SVCB、HTTPS、TLSA 等很多免费解析商都不支持的现代类型。默认 TTL 300 秒，改动通常 5–10 分钟生效，全球最长 48 小时。

两个常用例子：

- 指到自己的服务器：加一条 **A** 记录，主机名填 `@`，值填服务器 IP。
- 指到 GitHub Pages：加一条 **CNAME** 记录，主机名填 `@`（或子路径名），值填 `你的用户名.github.io`。

### 方式二：接 Cloudflare（官方有专门教程）

想用 Cloudflare 的解析、免费 SSL 和防护，官方给了一份完整的 7 步教程：

1. 登录 Cloudflare 后台，点 **Add a Site**，填入你的**完整子域名**（如 `yourname.indevs.in`，不要只填主域名），选 **Free** 免费计划。
2. 记下 Cloudflare 分配给你的两个 NS（每人不同，形如 `ava.ns.cloudflare.com`）。
3. 回到 StackRyze 后台：**My Domains** → 点你的域名 → **DNS Configuration** → **Edit**，填入 Cloudflare 的两个 NS，保存。
4. 回 Cloudflare 点 **Check nameservers now**，等它验证通过（通常几分钟，最长 24 小时，会发邮件通知）。
5. 在 Cloudflare 的 **DNS → Records** 里加解析记录。指 GitHub Pages 的例子：类型 CNAME、名称 `@`、目标 `你的用户名.github.io`、代理状态选 **DNS only（灰云）**、TTL 自动。
6. 到 **SSL/TLS** 把模式设为 **Full** 或 **Full (strict)**，打开 **Always Use HTTPS**。刚开始建议所有记录先用灰云跑通，再考虑开橙云代理。

**NS 规则要知道**：按官方概念文档，`ns1.stackryze.com` 和 `ns2.stackryze.com` 这两个官方 NS 是**强制保留、删不掉**的，在此之外最多再加 4 个自定义 NS（总上限 6 条）；想完全只用第三方 NS，需要发邮件联系官方客服处理。所以接 Cloudflare 后，记录到底以哪边为准，跟着实际生效的 NS 走，别两边同时乱改。

## 续期操作（附论坛说法核对）

1. **什么时候能续**：到期前 60 天进入续期窗口，后台域名状态会变成「Expiring Soon」，官方会在到期前 60 天和 10 天各发一封提醒邮件，邮件里带续期直达链接。
2. **怎么续**：后台 **My Domains** → 点 **Renew** → 确认。免费，续完到期日往后推 1 年——注意是从**原到期日**起算，不是点哪天从哪天算，早续不吃亏。
3. **可以叠加**：每天最多续 1 次，多次续期年限叠加，想一次多保几年可以分几天点。
4. **过期了还有救**：过期后 15 天是宽限期，解析照常工作、记录还能改、还能续期。但第 15 天一到，解析被删除、名字进入 7 天冷却期，第 22 天起谁都能抢注，**原主人没有任何优先权**。宽限期也别拖，设好日历提醒。

**核对论坛说法**：LINUX DO 近期有帖子说 StackRyze 的域名到期后「进入管理页面点击刷新后自动续期」。对照官方文档，实际按钮叫 **Renew（续期）**，不是刷新网页；「免费续 1 年」这点属实，操作以本文为准。

## 关于「账户验证」：基础使用不用绑卡

网上有资料提到 StackRyze 验证账户要绑支付方式，这里按官方验证文档说清楚：

- **基础注册、领域名、用自带 DNS：不需要账户验证，不绑卡，零费用。**
- 「账户验证」是一个**可选**的一次性步骤，只在你要用高级功能时才需要：签发 API 令牌、开启 DNSSEC、使用 Webhooks、接入你自己的域名，或提高解析的区域/记录数限额。
- 验证方式二选一：① 拿一个你自己的域名，按提示加一条 TXT 记录证明所有权；**或者** ② 绑一张支付方式做一笔 **$0 预授权（立即退回）**。不想绑卡，选 TXT 记录那条就行。

## 适合 / 不适合

**适合：**

- 个人项目、作品集、毕设演示，给 GitHub Pages / Vercel / 自有小服务器配一个好记的地址
- 想把解析放 Cloudflare、要免费 SSL 和基础防护的小站
- 一次想备齐几个不同后缀、各占一个坑位的开发者
- 练手、测试、临时活动页这类丢了也不心疼的用途

**不适合：**

- 正经商业站、长期品牌官网：域名所有权不在你手里
- 需要把域名转出到其他注册商的：官方明确写了**不可转出**，名字一辈子绑在所选后缀下
- 收重要邮件的生产域名：免费二级域名做 MX 在技术上可行，但稳定性和信誉都别指望
- 无法承受平台变动的服务：平台停服或改规则，你名下所有域名一起受影响

## 和 isroot.in 的区别

同是免费二级域名，两家路数不完全一样：

- **后缀与配额**：StackRyze 是 4 种后缀、各领 1 个（共 4 个）；isroot 只有 `.isroot.in` 一个后缀，但同后缀可领多个（默认 1 个，给官方仓库点 Star 后解锁到 5 个）。
- **PSL**：StackRyze 的 indevs.in、sryze.cc 已进公共后缀名单；isroot.in 未进——这也是 isroot 改 NS 受限、接不进 Cloudflare 免费版的重要原因。
- **接 Cloudflare**：StackRyze 有官方完整教程、明确支持；isroot 官方两种口径互相矛盾，免费版 Cloudflare 明确接不了。
- **注册方式**：StackRyze 邮箱或 GitHub 都行；isroot 只能用 GitHub 登录。
- **相同点**：都是二级域名、有效期 1 年、靠每年手动免费续期、域名所有权归平台。

## 风险提示

1. **所有权不在你手里**：4 个后缀域名都属于 Stackryze 注册局，官方原话是你「租」了下面的一个位置。不能转出、不能过户，平台就是规则本身。
2. **平台可持续性风险**：这是个仍在快速迭代的年轻项目（2026 年 7 月才发 1.0），连官方文档内部都存在配额写 4 个还是 5 个这种口径不一致。免费服务关停、改规则的先例不少，重要项目请用自己花钱买的域名。
3. **滥用会被处置**：官方把垃圾邮件、钓鱼、挂马分发、端口扫描、撞库等列为滥用，处理流程是先暂停相关解析/记录，严重或屡犯直接删名。正常建站不用担心，但别拿它做灰产测试。
4. **忘续 = 丢名**：宽限期只有 15 天，过期满 22 天名字就可能被别人注册走，且没有找回通道。领完就把续期提醒写进日历。
5. **信任背书弱**：二级域名不适合收款页、对外商务、需要用户输入敏感信息的场景，访客和部分平台风控对这类域名的信任度天然更低。
6. **平台只给域名不给空间**：领完域名还得自己有服务器或托管平台放网站，别把它当成「免费建站全家桶」。

## 总结

StackRyze 是目前免费二级域名里功能比较完整的一个：4 种后缀可选、两个主力后缀进了 PSL、自带解析记录类型齐全、官方教程支持接 Cloudflare、续期免费还能叠加年限。代价也还是那句老话——它是个二级域名，所有权和生杀大权都在平台手里。拿来给小项目、练手和演示站配地址很合适；真要长期经营的项目，还是花几十块买个自己的域名更踏实。
