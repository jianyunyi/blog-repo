# MiMo-V2.5 明天上午 10 点下线：V2.6 迁移动手清单（2026-10-20）

> 一句话导读：小米官方公告，mimo-v2.5-pro / mimo-v2.5 在 2026-10-21 10:00（北京时间）正式退役。代码里还在用旧模型名的，今天花 10 分钟换掉，否则明天请求直接失败。

## 前置条件

- 你的代码、Agent 工作流、Pi/Ling 配置里，用到了 MiMo API（model 字段是 `mimo-v2.5-pro` 或 `mimo-v2.5`）
- 能改代码并发起一次测试请求；改完跑一遍回归再上线

## 分步骤

### 第一步：确认官方下线公告，记住映射关系

小米在 MiMo 开放平台文档里发了正式的 deprecate 公告，时间线很清楚：

![小米 MiMo 官方下线公告：V2.5 系列 10-21 10:00 退役](img/2026-10-20-MiMo下线/step1.png)

- `mimo-v2.5-pro` → `mimo-v2.6-pro`（升级点：旧版只支持文本输入，新版支持多模态理解）
- `mimo-v2.5` → `mimo-v2.6-flash`（注意参数默认值变了，见第三步）
- 2026-10-14 18:00 起，旧模型名的请求已**自动路由**到新模型；**2026-10-21 10:00 后，旧模型名彻底失效**，请求直接报错。

### 第二步：全局搜索旧模型名，换成新 ID

在你的项目里搜 `mimo-v2.5`：

```bash
# 找出所有引用旧模型的地方
grep -rn "mimo-v2.5" --include="*.py" --include="*.ts" --include="*.js" --include="*.json" --include="*.yaml" .
```

替换映射：

| 旧（明天失效） | 新（换上） |
|---|---|
| `mimo-v2.5-pro` | `mimo-v2.6-pro` |
| `mimo-v2.5` | `mimo-v2.6-flash` |

走 OpenRouter 调用的注意：OpenRouter 上的新模型 ID 是 `Xiaomi: MiMo-V2.6-Pro` / 对应的 Flash 版本，价格和官方一致——Pro 版 $0.435 / $0.87（输入/输出每百万 token），Flash 版 $0.14 / $0.28，官方说 V2.6 维持了上一代定价。

![OpenRouter 上小米模型页：V2.6 系列价格与模型列表](img/2026-10-20-MiMo下线/step2.png)

### 第三步：检查三个参数变化，别直接裸换

官方公告里明确写了 V2.6 的参数行为变化，裸换模型名可能行为不一致：

1. **thinking 模式下不再支持自定义 `temperature` / `top_p`**：v2.6-flash 和 v2.6-pro 会强制用 `temperature: 1.0`、`top_p: 0.95`，你传了也白传。之前调过采样参数的，把相关逻辑删掉或注释掉。
2. **`max_completion_tokens` 默认值变了**：mimo-v2.5 默认 32768，mimo-v2.6-flash 默认 131072。如果你之前依赖默认值做截断/分页，换模型后输出可能变长 4 倍——要么显式传参锁死，要么检查下游处理逻辑。
3. **多模态是新增能力**：mimo-v2.6-pro 现在支持图文输入，如果你之前因为 v2.5-pro 不支持图片而绕路（先调别的视觉模型），可以简化链路了。

### 第四步：回归测试，重点看这三项

换完先别直接上生产，跑一遍：

- 长文本任务：v2.6-flash 默认 max tokens 变大，检查超长输出有没有把下游撑爆
- Agent 多步任务：v2.5-pro 在第三方实测里 agent 任务平均分 87.5%（coding 单项 97.9%），v2.6 官方称推理更强——用你自己的任务集对比一下，别假设"新的一定更好"

![第三方实测：mimo-v2.5-pro 的 agent 任务 benchmark 分数](img/2026-10-20-MiMo下线/step3.png)

- 计费：价格没变，但输出变长 = token 变多 = 账单变多，盯一眼用量面板

## 注意事项、费用、坑点

- **DDL 是明天 10:00（北京时间）**：10-14 起的自动路由只是过渡期，21 号 10 点后旧名直接 404/报错。定时任务、cron 里写死的模型名最容易漏，用第一步的 grep 全扫一遍。
- **价格不变不等于账单不变**：单价没变，但 max_completion_tokens 默认值翻 4 倍，输出 token 多了账单自然涨。对成本敏感的任务显式传 `max_completion_tokens`。
- **thinking 参数静默失效最坑**：传了 temperature/top_p 不报错、直接被忽略，效果和你预期的不一样，排查时先看这一项。
- **OpenRouter 用户**：模型名带 `Xiaomi:` 前缀，别和官方直连的 `mimo-v2.6-pro` 搞混；走 OpenRouter 还能顺手对比下别家模型，但注意缓存命中率影响实际账单。
