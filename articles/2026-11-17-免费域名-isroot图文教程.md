## isroot.in 是什么

isroot.in 是一个面向开发者、学生和独立开发者的**免费二级域名**服务，由 NeverCode 团队维护，项目本身在 GitHub 上开源（仓库 nevercode-in/FreeDomains，AGPL-3.0 协议）。

它提供的不是 `yourname.com` 这种你真正拥有的独立域名，而是挂在它主域名下面的二级域名：

```
yourname.isroot.in
```

比如 `blog.isroot.in`、`api.isroot.in`、`myproject.isroot.in` 这种形式，前缀可以自己挑（没被别人注册、且符合命名规则即可）。平台只提供域名和 DNS 解析管理，**不提供服务器和网站空间**——网站内容还是要放在你自己的服务器或 GitHub Pages、Vercel 这类托管平台上，再用解析指过去。

## 注册与领取步骤（完整版）

**第 1 步：用 GitHub 登录**
打开官网 isroot.in，点 **Get Started**，按提示填写名字、过验证码，然后选 **Signup with GitHub**，在 GitHub 页面完成授权。官方文档明确说：目前只支持 GitHub 这一种登录方式，没有 GitHub 账号的先去注册一个（免费）。

**第 2 步：注册第一个域名**
登录后进入后台的 **Subdomains**，打开创建表单，输入你想要的前缀（只填前缀，不要带 `.isroot.in`，也不要带 http 或路径），过验证码，点 **Create Subdomain**。看到 `你的前缀.isroot.in` 出现在子域名列表里，就注册成功了。注册时平台会自动尝试完成初始 DNS 设置；如果后台出现 **Retry setup / migration** 按钮，在 DNS Records 里点它重试即可。

**第 3 步：解锁到 5 个名额（可选）**
默认只有 1 个名额。想拿满 5 个：在后台提示里找到 **Star repo** 入口，用**登录 isroot 的同一个 GitHub 账号**给它链接的官方仓库（nevercode-in/FreeDomains）点一个 Star，回到后台点 **Refresh status** 刷新状态，额度就会提升到总共 5 个。注意是「总共 5 个」，不是在 1 个之外再加 5 个；而且每注册一个要等 1 小时冷却，所以 5 个最快也要分几个小时领完。

## DNS 解析设置步骤

注册成功只是占了个名字，要让它能访问你的网站，还得加解析记录：

1. 后台进入 **DNS Records**，选中你要配置的子域名；
2. 点 **Add Record**，选择记录类型：**A**（指向 IPv4）、**AAAA**（指向 IPv6）、**CNAME**（指向另一个主机名）、**MX**（邮件）、**TXT**（验证文本）；
3. 填 **Name/Host**、**Value** 和 **TTL**；MX 还要填优先级（0–65535）。保存后在记录列表里确认出现即生效，官方称大多数修改即时生效，全球同步可能需要几分钟。

几个最常用的填法：

- **指向自己的服务器**：类型选 A，Name 填 `@`（代表 `你的前缀.isroot.in` 本身），Value 填服务器公网 IPv4。
- **再配一个 www**：Name 填 `www`，就是 `www.你的前缀.isroot.in`，可以单独指到别处。注意 Name 是相对写法：填 `@` 是域名本身，填 `www` 是它的下一级，千万别把完整地址粘进去，否则会拼成一串重复后缀。
- **指向 GitHub Pages**：类型选 CNAME，Name 填 `@`，Value 填 `你的用户名.github.io`；然后去 GitHub 仓库设置里把这个域名填为自定义域名。CNAME 和 MX 的值只填主机名，不要带 `https://`、端口或路径。
- **验证类需求**（比如搜索引擎站长验证、某些平台的域名所有权验证）：用 TXT 记录按对方给的字符串填即可。

改完想验证是否生效，可以在本地终端用 `dig 你的前缀.isroot.in A +short` 查一下（Windows 可用在线 DNS 查询工具代替）。

## 续期：别忘了这一年一次的动作

- 每个域名有效期 365 天，到期时间在后台 **Subdomains** 里能看到，平台也会发提醒邮件；
- 到期前 60 天，后台出现 **Renew**（或在 Manage 里点 **Renew Domain**），点一下即可免费续期，一次续 365 天，不花钱、不用绑卡；
- 万一过期了，还有 7 天宽限期可以走同样的续期流程；超过宽限期、或域名处于被暂停状态，就续不了了，只能联系客服，且不保证能要回来；
- 删除是**永久删除**：在 Manage 里 Delete 需要输入 DELETE 确认，删了别指望还能把同一个名字注册回来。

建议领完就给自己设个日历提醒（比如到期前 30 天），这是这类免费域名最常见的翻车点——不是收费，是**忘续**。

## 关于「改 NS / 接入 Cloudflare」：官网自己都说法不一

这一节要专门提醒，因为网上很多教程会说「可以托管到 Cloudflare」，实际情况比较微妙：

- 官网首页 FAQ 写的是：**自定义 NS 暂不支持**，原因是 isroot.in 还没有进入公共后缀列表（Public Suffix List），并说「即将推出」；
- 但官方文档里却已经有完整的 **Edit Nameservers** 操作说明：可以在后台把 NS 改成外部 DNS 商家的两台服务器（表单只有 NS1、NS2 两个空），文档还给了 deSEC、Bunny DNS 的对接示例；
- 对 Cloudflare，官方文档的口径很明确：**免费版 Cloudflare 接不了**——给这种二级域名单独建 zone 需要 Cloudflare 的企业版子域名功能，普通免费开通不是受支持的路径。所以「把 isroot 域名托管到 Cloudflare DNS」目前基本走不通；但把记录 **CNAME 指向** Cloudflare Pages 等服务的地址，是另一回事，没问题。

两个口径冲突时，以你自己后台里实际能点的功能为准；就算改 NS 成功，也要注意：改完之后 isroot 后台的 DNS 编辑会停用，记录要去外部商家那边管，且官方提醒 NS 变更最长可能要 24–48 小时才完全生效。

## 适合 / 不适合

**适合：**

- 给个人博客、作品集、毕设、练手项目配一个好记的免费地址；
- 给自己部署的 API、测试服务、NAS/个人服务器（配合 A 记录/DDNS 思路）留个固定入口；
- 多个小项目各配一个独立网址，又不想为每个都买域名续费的人。

**不适合：**

- **正经长期业务、网店、要收款的站点**：域名所有权不在你手里，别把身家性命放上面；
- 需要把 DNS 托管到 Cloudflare（免费版）的场景；
- 需要 NS、SRV、CAA 等更多记录类型，或要给域名做所有权转移、过户的场景；
- 拿它当主邮箱域名要格外谨慎：MX 虽然能配，但域名一旦过期或被收回，邮件会跟着一起丢。

## 风险提示：免费二级域名的固有风险

这类服务省钱，但下面几条是结构性的，不是 isroot 一家的问题：

1. **所有权归平台，不归你。** `isroot.in` 主域名属于 NeverCode 团队，你只有使用权。平台改规则、停服务、甚至关停，你的地址都会跟着没——重要项目请始终以自己买的独立域名为主，这个只当备用和练手。
2. **违规会被直接收回。** 平台设有滥用举报通道，钓鱼、垃圾邮件、恶意软件、抢注商标名等用途会被撤销；具体禁止清单以官网服务条款与使用政策的最新版本为准，注册前建议自己扫一眼。
3. **没进公共后缀列表（PSL）的兼容性问题。** 有些托管平台、验证系统会因为它不是 PSL 后缀而拒绝绑定或区别对待；不同子域名之间在浏览器看来也同属一个「站点」，cookie 隔离不如独立域名干净。绑定第三方平台前先小规模试通再正式用。
4. **忘续 = 丢失。** 365 天到期、60 天续期窗、7 天宽限，错过之后名字可能被别人注册走。设提醒，别偷懒。
5. **平台还很年轻。** 项目 2026 年初才开源上线，文档自称还在 beta；服务稳定性、长期存续都没有历史背书。代码在你的仓库里、数据做好备份，就不怕它哪天突然下线。

## 总结

isroot.in 是个规则写得还算坦诚的免费二级域名服务：GitHub 登录、免绑卡、默认 1 个、点个 Star 解锁到 5 个，A/AAAA/CNAME/MX/TXT 该有的解析都有，每年记得免费续一次期。视频里「永久免费、一次拿下 5 个」的说法要打个折听——本质是「可长期免费续用的二级域名，需要手动解锁和续期」。

拿它给小项目配个好记的地址，完全够用；但请记住那句老话：**免费的域名再方便，也不是你的资产。** 真正在乎的项目，花十几块钱买个自己的域名，才是睡得着觉的做法。
