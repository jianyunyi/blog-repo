# 免费域名：is-a.dev 图文教程——不用买域名，用一个 GitHub PR 领一个 .is-a.dev 子域名

**一句话导读：** 有个人作品集、博客或开源小项目，却不想先花钱买域名的时候，is-a.dev 给开发者免费发 `你的名字.is-a.dev` 这样的子域名：不用信用卡、不用注册商，全程就是在 GitHub 上 fork 一个仓库、加一个 JSON 文件、提一个 PR，等维护者合并后解析就生效；代价是它只给个人开发类项目用、商业站会被拒，而且要等人工审核，不是秒开通。

## 前置条件（需要什么）

- 一个 GitHub 账号
- 一个已经能打开的个人网站或开发类项目（作品集、博客、开源项目页都行；空白页、内容极少的半成品会被拒，先把站做得像个样子再申请）
- 这个站已经有地方托管（GitHub Pages、Cloudflare Pages、Vercel 等都行，本文以 GitHub Pages 为例）
- 心理预期：这不是买域名，你拿到的是共享主域名下的一个子域名；改解析也要再提 PR，没有即时生效的控制面板

## 分步骤

### 第 1 步：先看 is-a.dev 官网，确认它到底给什么

![is-a.dev 官网首页](img/2026-10-31-isadev/step1.png)

打开 is-a.dev 官网先看定位：它是一个社区驱动的免费子域名服务，面向开发者个人使用，解析跑在 Cloudflare 的网络上。因为它进了 Public Suffix List（公共后缀列表），很多平台会把它当成一个独立域名来对待，限制比普通二级域名少。但它不是注册商：你买不到 `is-a.dev` 本身，也拿不到顶级域名，只能申请 `xxx.is-a.dev`。

### 第 2 步：读官方文档的快速上手，核对申请资格

![is-a.dev 官方文档快速上手页](img/2026-10-31-isadev/step2.png)

官方文档的快速上手页把资格写得很直白，申请前逐条自查，省得 PR 被打回：

1. 网站至少“基本完成”，不能是空白页或只有两行字的占位页。
2. 必须是个人网站（如开发相关的作品集、博客）或非商业的开发类项目；商业用途的站，维护者有权直接关闭 PR。
3. 文件名就是你要的子域名：全小写 + `.json`，比如想要 `zhangsan.is-a.dev`，文件就叫 `zhangsan.json`。
4. 官方文档明确提醒：不要用 AI 生成申请文件，“它总会写错、只会拖慢你拿到域名的时间”——照模板手写，别图省事。

另外两个硬限制先记下：常见保留名（`www`、`api`、`mail` 等）和单字符子域名注册不了；NS（ nameserver 托管）只在特批情况下才给，且一般要求子域名已存在 30 天以上——普通人用 CNAME 或 A 记录就够了，别一上来就要 NS。

### 第 3 步：Fork 仓库，在 domains 目录里新建你的 JSON 文件

![is-a-dev/register 仓库页](img/2026-10-31-isadev/step3.png)

打开 `github.com/is-a-dev/register`，点右上角 Fork，把仓库复制到你自己的账号下。进你 fork 里的 `domains/` 目录，点 Add file → Create new file，文件名写 `你的子域名.json`。

以指向 GitHub Pages 为例，文件内容按官方模板写（把占位符换成你自己的）：

```json
{
  "owner": {
    "username": "你的 GitHub 用户名",
    "email": "你的邮箱"
  },
  "record": {
    "CNAME": "你的 GitHub 用户名.github.io"
  }
}
```

指向其他托管商时，record 里就填对方给你的记录（A 记录填 IP，CNAME 填对方给的主机名），以托管商的接入手册为准，不要凭印象编。写完先用 JSON 校验工具（如 jsonlint）过一遍：少个逗号、多层括号，PR 的自动测试就会直接报错。

### 第 4 步：提 PR、过自动测试、等人工合并，然后等解析生效

![is-a.dev 申请步骤详解](img/2026-10-31-isadev/step4.png)

保存文件后 GitHub 会提示你开 Pull Request：按 PR 模板把检查清单勾完，确认你的项目是开发相关的、不是商业站，然后提交。提交后先是自动测试校验你的 JSON 格式和记录合法性，过了才进人工审核队列；实测教程给出的典型审核时间是 24–72 小时（以维护者实际处理为准，不是承诺）。

合并后 DNS 解析最长需要约 24 小时全球生效，别一合并就反复改记录。生效后访问 `你的名字.is-a.dev`，能打开你的站就成了；如果用 GitHub Pages，记得在你的 Pages 仓库设置里把自定义域名填成这个子域名，并打开 Enforce HTTPS。以后想改解析、换托管：改你 fork 里同一个 JSON 文件再提一次 PR 即可；想注销：删掉这个文件再提 PR。

## 注意事项、费用、坑点

- **费用：** 全程 $0，无信用卡、无隐藏收费；但它不提供托管，托管商那边的费用另算（GitHub Pages、Cloudflare Pages 的静态托管本身也是免费档可用）。
- **前科核查：** is-a.dev 是社区志愿维护项目，不是商业注册商，没有“批量封号牟利”的前科；但它的命脉就是志愿者合并队列——队列一慢，申请就得等；且规则由维护者说了算，商业站、空白站被拒是明文规则，不是针对谁。把它当成个人项目的免费门面可以，别把公司官网、生意收款页押在它上面。
- **别踩的坑：** ① 站还是空白页就去申请，白等一轮被拒；② 商业项目、带收款的着陆页去申请，按规则会被关闭 PR；③ 用 AI 现成生成的 JSON 直接提交，格式最容易错，先本地校验；④ 合并后立刻断言“没生效”，DNS 全球生效最长约 24 小时，先等；⑤ 以为拿到的是顶级域名——它永远是 `xxx.is-a.dev`，换品牌时要重新申请，旧链接也带不走。
